# 로드맵 메모

다른 컴퓨터에서 이어서 작업할 때 맥락을 잃지 않도록 남긴 결정과 후보 목록이다. 구현된 것은 `CLAUDE.md`가 기준이고, 이 문서는 **앞으로 할 일**만 적는다.

기준 시점: 2026-10-19, 브랜치 `feat/android-spike`(PR #2).

## 방향

"태블릿에서 펜으로 PDF를 읽고 메모하는 가벼운 앱"을 가장 앞에 둔다. 변환은 데스크톱의 보너스다.
양식·서명·교정 같은 영역으로 넓히지 않는다(같은 영역을 가는 큰 프로젝트가 이미 있고 따라잡기 어렵다).
Rust로 처음부터 만든 PDF 엔진 PdfCraft(https://github.com/storytold/pdfcraft, 알파)와 비교해 정리한 차별점: 안드로이드 태블릿·펜 입력, 이미지·SVG·AI 변환 허브,
한국어 우선 경험, 검증된 엔진(PDFium)과 좁은 범위. (README만 읽고 비교한 것이고 직접 써 보지는 않았다.)

## 다음 단계: 자동 저장·복구 (결정됨)

**왜**: 태블릿에서 메모하다 앱이 꺼지거나 배터리가 나가면 저장 안 한 주석을 잃는다. 주석은 열린 문서(메모리)에만 쓰이고 저장 단추를 눌러야 파일이 된다.
PdfCraft는 1분마다 자동 저장하고 다시 열 때 복구를 제안한다. 같은 수준을 목표로 한다.

**지금 코드의 사실** (설계 전에 확인한 것)
- 주석은 `AnnotationState`가 열린 문서에 바로 쓰고 `dirty`로 저장 여부를 안다. 저장은 `document.encodePdf()`를 새 파일로 쓴다(`ViewerScreen._save`, 모바일은 `_saveMobile`).
- `encodePdf()`는 파일 전체를 메모리에 올린다(2GB 문서 ≈ 2GB). 자동 저장을 자주 하면 큰 문서에서 부담이 크다.
- 모바일은 열린 파일을 앱 보관함에 복사해 쓴다(`OpenedFiles`). 데스크톱은 원본을 연다.
- 저장 안 한 주석이 있으면 나갈 때 묻는다(`PopScope`). 비정상 종료에는 아무 대비도 없다.

**설계 초안** (아직 구현 안 함, 정하지 못한 것은 아래 "열린 질문")
- 원본은 건드리지 않고, 앱 지원 폴더에 **복구용 사본**(`recovery/<문서 경로의 해시>.pdf` + 원본 경로·시각 메타)을 쓴다. 쓰기는 `.tmp`에 쓴 뒤 이름을 바꿔 넣는다(원본 저장과 같은 원칙).
- 언제: 주석을 바꾼 뒤 일정 시간(예: 30~60초) 조용했을 때, 그리고 앱이 백그라운드로 갈 때(모바일 `AppLifecycleState.paused`). `dirty`일 때만 쓴다.
- 정리: 사용자가 저장하거나 "저장 안 함"으로 나가면 복구 사본을 지운다.
- 복구: 문서를 열 때 복구 사본이 원본보다 새것이면 "저장하지 않은 작업이 있어요. 복구할까요?"를 묻는다. 복구하면 사본으로 열되 `dirty`를 켜서 저장을 이어가게 한다. 거절하면 지운다.
- 큰 문서: 크기 한도(예: 200MB 이상은 자동 저장 간격을 늘리거나 끈다)를 두고 사용자에게 알린다.

**열린 질문**
- 다른 컴퓨터로 옮겨 작업할 때 복구 사본은 따라가지 않는다(기기 안에만 있다). 기기 간 이동은 "저장한 PDF를 옮기는 것"으로 두고, 복구는 한 기기 안의 비정상 종료만 다룬다 — 이 선을 유지할지.
- 북마크는 경로별로 따로 저장되므로(`BookmarkStore`) 파일을 다른 컴퓨터로 옮기면 따라가지 않는다. 같이 풀 것인지(예: 사이드카 파일, 또는 PDF 안에 표준 목차로 쓰기 — PDFium에 북마크 쓰기 API가 없어 어렵다).
- 복구 사본이 문서의 어느 버전에서 나왔는지(원본이 그 사이 바뀌었을 때) 알아내는 방법: 원본 크기·수정 시각·해시를 메타에 담는다.
- 시험: 비정상 종료는 통합 시험에서 흉내 내기 어렵다. 복구 파일 쓰기·읽기·정리 로직을 `AnnotationBackend`처럼 인터페이스 뒤에 두고 단위 시험을 한다.

## 그다음 후보 (순서 미정)

- **한 쪽씩 보기·두 쪽 보기**: 지금은 쪽 이어 보기만 된다(pdfrx `layoutPages`를 직접 짜야 한다).
- **마지막으로 읽은 쪽 기억하기**: 다시 열면 읽던 자리로. 작고 효과가 크다.
- **본문 검색에 메모 내용 합치기**: 지금 주석 목록 필터와 본문 검색(⌘F)은 따로다.
- **다크 모드 보기**: 흰 쪽을 어둡게.
- **문서 속성 창**, **원본에 저장**(영구 URI로 제자리 저장, 모바일).
- **모바일 마무리**: 폰 화면 레이아웃, 릴리스 서명·스토어 배포(모바일 규약), iOS.
- **실기기 확인이 남은 것**: 실제 S Pen 동작, 두 손가락 확대, 북마크·주석 검색·사이드바 끌기의 태블릿 화면.
